Dezaemon 2 Parity Mapデザエモン2

What the importer already decodes of a Sega Saturn Dezaemon 2 save, and what still stands between it and full feature parity. Target is the Saturn release (big-endian SH-2, BackUpRam Format BUP saves, LZSS-compressed 8-section payloads) — not the SNES original. The canonical RE notes live in packages/shmup-engine/FORMAT.md; the whole pipeline is currently import-only.

.sav → bup-parse → decompress (LZSS) → decode sec0–3 CG · sec4 palettes · sec5 stages · sec6 BGM · settings → mapSaveToGame → editor game.json → Phaser runtime
Implemented container · graphics · levels · enemies · bosses · items · BGM · 3D decode Partial data landed, runtime pending Absent write path, horizontal, 2P, endings

01What remains

Two reverse-engineering blitzes (2026-08-28) closed most of the original twelve items; what follows is the residue. SPEC WRITTEN means the layout is traced and documented in FORMAT.md and only the runtime is missing; MEANING OPEN means the bytes are located but their semantics are untraced; NO TRACE means nothing exists yet.

  1. 1

    Write path — .sav exportNO TRACE

    Unchanged, and still the single largest missing capability: no LZSS compressor, no section-table/checksum builder, no BUP block allocator anywhere (grep over src finds only decompress). The real compressor lives in the disc's S_OPT.bin. Until this exists the editor can never round-trip a game back to a Saturn cart, so the pipeline stays import-only.

  2. 2

    Horizontal scrolling & two-player at runtimeSPEC WRITTEN

    The bytes are decoded — settings gameMode bit0 = horizontal, bit1 = two players — and the import now warns rather than silently lying (map-to-game.js:674). The work left is presentation, not RE: the world simulation is orientation-invariant, so only the playfield mapping, input and spawn edges change. A large slice of the corpus is horizontal (Biometal Gust, Air Streamer…), and until this lands their stages read sideways.

  3. 3

    BGM accompaniment patterns & real instrument timbresSPEC WRITTEN

    Song timing is now engine-exact and the 1,260 kernel accompaniment rows plus the 116-instrument tone-bank map are extracted and shipped (data/bgm-accompaniment.json · data/bgm-instruments.json) — but nothing plays them. Parts are still hard-assigned square/square/triangle/noise, so an imported song has the right notes and tempo with the wrong voices and no auto-accompaniment. The instrument map carries SNDPAC.BIN offsets; that file is disc content and must never be committed.

  4. 4

    Bombs, charge shots and option pods at runtimeSPEC WRITTEN

    The four weapon-loadout presets are fully traced — main 0–7, sub/option 0–7, charge 0–3, bomb type + variant, each with its dispatcher and per-type attack powers (FORMAT.md +0x14–+0x1B). The runtime still only fires the main shot: bomb pickups increment a stock counter, charge and option pods do nothing. (Note the traced surprise: no bomb is a screen-clear — they are large piercing contact objects.)

  5. 5

    Title scene — draw the decoded art, and the entrance sequencerMEANING OPEN

    The title compositions decode correctly now (the 8×4 + 8×4 layout was corrected), and staff-role labels come from the save — but the title scene does not draw them, so imports still get a static logo blit. The 15-slot entrance-effect sequencer that animates a real Dezaemon title is untraced.

  6. 6

    sec7 part-shape meshes (ポリ吉 primitives)MEANING OPEN

    The model section itself is decoded — 16 slots × 328 B, 9 parts × 36 B, positions/rotations/scales in 16.16, slot stride confirmed against POLYKITI's literal pools (decode-model.js). What is missing is the other half: the primitive meshes are engine-fixed inside the POLYKITI overlay and untraced, so a model decodes as transforms over shapes named only by number.

  7. 7

    Bullet steering states 17 / 18 / 19MEANING OPEN

    All sixteen zako fire geometries are traced, but three per-bullet steering states they hand off to are not — geometry 8 is the 5-fan "with bullet state 19" and curves in a way the runtime approximates as straight (FORMAT.md:698 · game.bundle.js:3639). Affects the flight path of a minority of shots, not whether they appear.

  8. 8

    Open correctness risk: which record byte is HPMEANING OPEN

    A synthesis pass argues that record byte 2 bits 0–2 is HP, not speed — its table is difficulty-scaled into 0x06095040, which is provably the HP slot — and that byte 1's [60,30,15,…] is the animation-period pair instead. If true this inverts SPEED_TABLE/HP_TABLE and ripples through the mapper's hp/speed and the shot-damage divisor. Deliberately not acted on: the current model is self-consistent (LIFE stored <<8, three hits at max LIFE) and 12,800 raw units would be ~600 hits. Needs its own adversarial pass before anything is rewritten.

  9. 9

    Save-driven endingsNO TRACE

    The ending scene is still stock 2028-AI. Demo/attract recordings live on the retail disc rather than in saves, so this is bounded work — but nothing is decoded for it yet.

02Already implemented

Confirmed Checksum-proven or engine-disassembly-traced, and driven end-to-end by the runtime. These need no further RE work.

AreaCoverage
Containergzip .bcr / interleaved cart dumps / raw .bkr → BUP partitions, directory entries (Shift-JIS names, dates), fragmented block-chain reassembly, full 0x6C section-table + checksum validation, Okumura LZSS. bup-parse.js · payload-table.js · decompress.js
Graphicssec0–3 CG pages (8bpp, 16×16 cells), sec4 RGB555 palettes, background tilemaps with corrected flip bits, per-stage sprite composition bank with boss-core geometry, drawn title screens, and the save's own global art — player ship, item icons, bullet animations, blast frames. decode-cg.js · decode-sprites.js
LevelsPlacement grid (72 ids), stage count, per-(stage, record) enemy identity, and the authored scroll curve: speed table with easing, wave amplitude and type, per-stage extents. Spawns are scroll-position locked, so pacing survives the round trip. decode-stage.js · map-to-game.js
Enemy AIThe 18-byte record plus the engine's own choreography: all 256 appearance behaviour scripts (1,206 rows) interpreted live, the six hardcoded special classes 0x31–0x36, the 16-entry fire-geometry table with the 10/11/12 burst handlers, change-channel triggers at the traced pixel thresholds, and the hardware terrain-ride model — anchored riders recomputed absolutely from a map anchor, plain riders stepped by the frame's whole pixels, everything else holding station. decode-enemy.js · appearance-table.js · game.bundle.js
Death wordRecord bytes 2–3 — long mis-read as "fire type / fire params" — are the death word, now implemented in full: item drops by authored slot, child spawn of a successor at the dying enemy's exact position (inheriting an anchored parent's terrain anchor), and chain-kill of every object sharing a formation key in a four-tick ripple where each link runs its own death word. Byte 4 selects silent / small / full blast. decode-enemy.js · game.bundle.js
Bosses0x40 trailer decoded (size class, HP bands, pattern playlist, 4×14-byte patterns with 3 fire points) and all 32 engine movement scripts embedded with their step interpreter, including the arrive/death selectors that place the authored off-screen start, the death-drift target and the zoom/spin flourishes. decode-boss.js · data/boss-move-scripts.json
Items & weaponsEight item slots decoded as movement<<4 | type across nine types with their three launch behaviours, drops dressed in the save's own icons; weapon loadout presets and real per-level damage tables replace the refuted "+3 nibble = main weapon" reading. decode-settings.js · map-to-game.js
BGM / SFXsec6 fully decoded (24 songs × 32 measures × 4 parts × 16 steps, byte-exact tempo table, loop, echo, transpose) and synthesized live in WebAudio from the save's bytes — not prerecorded. Timing is engine-exact with no calibrated constants. SFX set honoured. decode-song.js · game.bundle.js
3Dsec7 decodes: magic, 16 model slots, 9 parts each, 16.16 positions / rotations / scales with mirror-by-negative-scale. decode-model.js

  • BGM accompaniment rows and the instrument tone-bank map ship as data but are never played data/bgm-accompaniment.json · data/bgm-instruments.json
  • 3D models decode to transforms, but with no mesh library to draw and no renderer decode-model.js
  • gameMode horizontal / two-player flags reach meta.dezaemonSettings and raise an import warning, nothing more map-to-game.js:617
  • Player 2's ship and loadout are decoded and then dropped map-to-game.js
  • Bomb, charge and sub-weapon types with their attack powers — decoded, never fired decode-settings.js
  • Title art and staff-role labels — decoded, not drawn decode-sprites.js · decode-settings.js

04No trace at all

Absent Real Dezaemon 2 features with no code behind them.

  • Any write path — LZSS compressor, section-table builder, BUP writer, .sav export (item 1 above)
  • Save-driven endings and the title entrance-effect sequencer (items 5 and 9)
  • The POLYKITI primitive mesh library behind sec7's shape descriptors (item 6)
  • Dev tooling referenced by FORMAT.md — dev/scan-compression.js, dev/decode-corpus.js, dev/diff-saves.js and the controlled-delta capture matrix exist only as plans; only dev-fixtures/debug-tools/render-chamber.ts survives
Sources: packages/shmup-engine/FORMAT.md (930-line canonical notes, split confirmed vs open), the decoder suite under packages/shmup-engine/src/decode/, and the 2028-ai runtime bundle. Everything marked implemented above was traced from SH-2 disassembly of GAME.CMP / 0KERNEL.BIN / KUMITATE and adversarially verified — verifiers caught real errors every round (inverted bit polarities, 90° angle conventions, unit scales), so no trace ships unverified. Confidence plumbing distinguishes confirmed / heuristic per section and the import sheet surfaces it in the editor. Surveyed 2026-08-28, after the second RE blitz.
